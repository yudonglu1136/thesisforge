# AI Insights：Discover 独立模块设计与实施方案

日期：2026-09-22。状态：保留原始产品与技术设计；随后已完成本地应用、接口、Fact OS 派生数据与每日同步挂接的实现，尚未部署到生产环境。

当前运行方式和实际数据合同见 [AI Insights 运维说明](ai-insights-operations.md)，验证结果及已知限制见 [本地验收记录](ai-insights-acceptance-2026-09-22.md)。本地公司登记已扩展为 59 家（9 家资本投入、28 家硬件、22 家软件，含 SNDK）。下文保留设计时的审查基线、候选清单和目标方案，不把设计建议自动视为已交付功能；完整租赁资本开支桥、历史可投资成员模式、首次披露切换等扩展仍需独立实现与验收。

## 1. 产品决定与替换范围

用户明确要求：彻底放弃 Discover 中的 Value Flow，用独立的 **AI Insights** 子模块替换。不是 Value Flow 的新 tab、增强面板或改名皮肤。保留 Discover 大模块及其他既有功能，新增独立页面、API、指标与排名引擎；Value Flow 的产业链卡片、面板和在线计算退出产品。

建议导航位置：`Discover → AI Insights`。进入公司的具体研究仍使用 `Research`，携带相同截止日和原始分析上下文。

产品要帮助用户回答四个问题：

1. 四大科技和 neocloud 的资本投入有多大，正在加速还是减速？
2. 硬件和软件公司的收入增速是否同步，增长扩散到哪些环节？
3. 哪些公司的收入增长更快，哪些真正转化成利润和现金流？
4. 回到某个历史时点，当时已经披露了什么，哪些结论当时能够成立？

核心使用路径：总览发现变化 → 子行业定位 → 个股排名与比较 → 来源核实 → Research 深挖并保存观察。

设计沿用 ThesisForge 深色与薄荷绿体系。资本投入、硬件、软件使用稳定的三种系列色；正负变化同时给符号，颜色不自动等于利好/利空。首屏优先保留季度、截止日、规模和趋势，避免再做很高的介绍区。

桌面允许图与证据侧栏同时查看；窄屏按规模 → 趋势 → 排名纵向排列，长表在自身区域滚动。EN/ZH 同时实现，英文模式不混中文动态文案。

### 总览的交互

- 点资本投入柱：选中该季度，展示各公司金额、贡献和缺失项。
- 点 neocloud 堆叠：展开 GPU 云、园区/托管、转型公司三类，避免混淆商业模式。
- 切 YoY/QoQ：趋势、贡献图和当前增速排序一起换口径；增长综合分保持既定公式，不偷偷换权重。
- 点某子行业热力格：打开该期该组完整公司排名。
- 默认显示 8 季，可查看 12/20 季；不足期保留实际长度。
- “同口径样本”开关显示固定篮子趋势；滚动样本的覆盖变化不能隐藏。

### 公司排名

筛选：硬件 / 软件 / 全部；子行业；收入规模；盈利状态；数据可比性。按市值筛选如被采用，市值也必须来自截止日前。

默认列：排名、公司、子行业、实际财报期末、披露日、收入、YoY、QoQ、增速变化(pp)、TTM GAAP经营利润率、TTM FCF率、SBC/收入、增长分、质量分、综合分、数据状态。

保存三种精简列预设：增长、盈利质量、综合。高级列包括毛利率、现金转化、应计项目、股本变化、库存/应收、客户集中度和估值。高级指标不因不覆盖而把整家公司隐藏。

“股票增速”默认指这些上市公司的营业收入增长；股价涨幅另有可选列/排序，明确标成 Price return / Total return，不能混入经营增长分。

排名变化显示两类：固定规则下公司的原始指标变化、同一规则/可比公司池下的名次变化。成员或方法发生变化时给出断点和新旧样本数，不把全部名次上升都写成经营改善。

### 公司对比和详情

最多比较 4 家，预设可选 CRDO / ALAB、AVGO / MRVL、LITE / COHR、MU / 其他已覆盖存储公司。共同展示八季收入、YoY/QoQ、TTM利润与FCF、评分拆解，而非来回切换单家公司。

公司详情侧栏显示本期与前期事实、增长贡献、利润到现金流的差异、排名组成、来源和不可比原因。底部 `Open Research` 保留 asOf、研究季度、筛选、排序、图表选择及证据ID，返回时恢复状态。

## 4. 公司池：覆盖清单是产品的一部分

把“全”定义为**清晰列出纳入、排除、待补数据和边界**，不宣称一个精选篮子等于全球 AI 产业。

资本投入默认覆盖用户指定的 MSFT、AMZN、Alphabet、META 加已核实的上市 neocloud。Alphabet 用 issuer ID 聚合一次，GOOG/GOOGL 不重复计算。ORCL 如扩展入投入侧，应标为额外 hyperscaler，不能改写“四大”的含义。

neocloud 候选至少审查 CRWV、NBIS、APLD、IREN、CORZ；逐公司逐期标注 GPU云/数据中心托管/矿业转型及披露范围。默认篮子可包含这些已核实成员，但子组始终可见，转型公司的集团资本支出不能直接称为 AI 资本支出。未上市且无连续公开财务的公司进入覆盖缺口，不以估算数悄悄填入主柱图。

硬件候选在原广篮子基础上核查以下环节，明确保留用户关心的 ALAB、MU、CRDO、AVGO、LITE、VRT：

| 环节 | 起始审查名单（不是数据已齐全的声明） |
| --- | --- |
| 计算与芯片 | NVDA、AMD、AVGO、MRVL、ARM、INTC |
| 存储 | MU、WDC、STX；补核独立NAND及非美股存储发行人 |
| 代工、封装与设备 | TSM、ASML、AMAT、LRCX、KLAC；补核测试/封装 |
| 网络、互连与光通信 | ANET、ALAB、CRDO、CIEN、COHR、LITE、APH |
| 服务器与制造 | SMCI、DELL、HPE、CLS |
| 电力与散热 | VRT、ETN；扩展相关电力设备公司时区分制造与公用事业 |
| 设计工具与IP（跨组观察） | CDNS、SNPS等属于EDA软件，计入软件收入；保留上游设计工具标签 |

软件候选：数据与AI平台 PLTR/SNOW/MDB/ESTC/AI/SOUN；可观测与云工具 DDOG/NET；企业工作流 NOW/PATH；安全 CRWD/PANW/ZS；应用 CRM/ADBE/APP/INTU/HUBS/TEAM。ORCL 单列混合业务，避免将集团全部收入宣传为软件或 AI 收入。

规则：

- 公司可拥有多个业务标签，但每个聚合视图只有一个明确主归属；所有标签筛选先按 issuer 去重。
- `businessModelGroup`（硬件/软件/云/混合）与 `supplyChainStage`（设计/制造/互连/应用等）分别维护；处于硬件上游不代表收入属于硬件。EDA软件不因供应链位置而计入硬件总额。
- 集团总收入篮子与 AI/数据中心分部收入篮子分开；分部与母公司不得叠加。
- AVGO等混合公司若按集团主归属进入硬件组，标签必须是“硬件组公司总营收”，其软件业务收入仍在集团内；纯硬件收入视图只能使用已披露分部，不能沿用集团数。
- 披露了收入的 AI 分部、ARR、订单、backlog、RPO 属于不同指标；ARR/订单不能填到收入行。
- 分部数据仅采用明确披露及来源；不能凭当前 AI 相关度乘总收入，生成“AI收入”。
- IPO前的经营财务若在后来招股书才公开，只能在该公开时点以后使用；历史上市股票排名还要符合当时上市条件。
- 非美股覆盖、币种、停牌/退市、并购/拆分和业务转型在登记中保留，不因当前无ticker而从历史清单删除。

## 5. 资本投入的三个口径

1. **报表现金投入代理**：复用供应商经核实的签名字段。若字段是固定/无形资产净现金流，正向投入定义为其相反数；资产出售净流入仍保留为负投入并标记。界面写明“净现金投入代理”，不用 `abs()`。这是基础覆盖视图。
2. **现金购置资本开支**：来源明确的现金PP&E/其他约定资本化支出，提供完整桥接；与净口径分别保存。数据未齐全时不能悄悄混入不同公司的gross/net数。
3. **新增资产投入（含融资租赁）**：现金购置加本期新增非现金融资租赁等受支持项目；租赁本金偿还、经营租赁付款、未来承诺和租赁总余额不等于当期新增资产。未披露的成员明确缺失。

每个视图按公司相同口径汇总，缺项显示已披露小计。后两个口径以来源覆盖为上线门槛；首版可以先提供准确命名的基础代理，不承诺 Fact OS 已有完整租赁桥。

本地字段字典还说明供应商会在某些不可取得/不可推导场景填0，因此0不自动代表经核验的“没有资本开支”。原始0保留，新增 `provider_zero_unverified`；涉及此项的完整覆盖、增长及评分须按证据状态处理，核实后才升级为真实零。

单季现金流来自受验证的 ARQ 单季值，不能再次差分。原始10-Q仅有YTD时才做 Q2=H1−Q1、Q3=9M−H1、Q4=FY−9M，全部组成必须在截止日前可知且会计口径一致。累计期/单季/TTM以类型字段约束。

图中称“四大 + 已覆盖 neocloud 的资本投入”，不称全球AI总投入。集团数字可能包含物流、办公、非AI业务；供应链收入存在上下游重复，资本投入、硬件收入、软件收入三条线不相加，也不计算伪“AI ROI”。

## 6. 规模、增速与贡献必须对得上

金额用 USD 的同类期间流量；非USD报表使用可追溯的期间汇率或经验证的provider USD字段。保留原币、转换依据和源时间。汇率未知则进入未覆盖，不能把本币当USD。美元增长和恒定汇率增长分别标识，后者只有真实披露/可核实换算才展示。

对同一配对成员集合 S：

```text
YoY(q) = sum(value[i,q], i in S) / sum(value[i,q-4], i in S) - 1
QoQ(q) = sum(value[i,q], i in S) / sum(value[i,q-1], i in S) - 1

weight[i] = prior[i] / sum(prior)
growth contribution[i] = (current[i] - prior[i]) / sum(prior)
sum(growth contribution) = aggregate growth
```

这是基期金额加权，不能用当前市值或当前期收入权重去平均增长率。所有参与值/币种/期间均需可比；前期总额<=0时百分比不适用，保留金额变化。公司盈利从负转正显示“扭亏”，不报失真净利润增长率。

已披露总金额的成员集合可能大于同比配对集合；卡片同时返回 `disclosedTotal` 和 `comparableCurrent/prior`，明确增长率对应后者。不能把同比配对集合算出的增长贴在不同范围的金额旁且不说明。

每张图必须能查看：计划成员、已披露成员、可比成员、缺失原因、数据期间跨度、主导贡献者；金额覆盖比例仅在分母可知时计算，不能把已披露金额当全部金额。

固定篮子指数只纳入整个窗口内可比且满足截止日的成员，单列被排除者；滚动配对增长的成员会变化，不默认连乘成固定篮子指数。公司拆分/并购发生业务范围变化时，已披露同比可单列，organic增长无证据则空缺。

显示8季YoY及TTM比较，需要向前多取基期；查询应至少覆盖显示窗口加7季，并额外获取各期间修订版本。不能只取8行就声称有8季同比和完整TTM同比。

## 7. 财季与季节性

统一使用一个有版本的财季映射，第一阶段采用校验后的 `calendardate` 对齐代理，并保留 reportperiod、fiscalYear、fiscalQuarter、periodStart/End。`reportperiod所属自然季`与provider `calendardate`不得混用。

聚合标题注明“按财季对齐”；tooltip显示实际期间范围。53周、财年变更、非标准期间和同一映射季度有两个报告的情况进入检查，不可用对象覆盖写法默默丢行。若以后按重叠天数估算自然季，只能另建估算视图，不覆盖已报告数据。

YoY看持续趋势，QoQ看边际变化。QoQ默认“未季调”；不同财季、季节性公司不能只靠一个环比排出“最好”。可补充今年QoQ减去年同一财季QoQ（pp），称“相对历史季节性变化”，不是正式季调结果。

## 8. 三种排名：先解释，再给分

所有权重是建议的 `ai-insights-score-v1` 产品规则，尚未证明能预测股票回报。原始指标与分数同时保留，不用分数代替事实。

### 增长

原始榜单提供 Revenue YoY / Revenue QoQ / 增速变化 / 美元收入增量四种直接排序，覆盖不完整也可以在有数据的单指标榜出现。

增长综合分 G：

| 输入 | 权重 |
| --- | ---: |
| 当季收入YoY | 40% |
| 当季收入QoQ | 30% |
| 收入YoY较上季变化（pp） | 15% |
| TTM毛利额YoY | 15% |

每项转为截至该时点同组可评分公司的百分位，0–100，越高越好。毛利基期非正则其百分比不可评分。原始增速不裁剪；百分位避免小基数极值无限拉高总分。

首版G明确标为未季调增长分，原始QoQ可能奖励季节旺季，详情同时展示去年同财季QoQ。可后续新增使用“本季QoQ−去年同财季QoQ”的独立评分版本；不能悄悄替换旧公式或把这个简单差值叫正式季调。

### 盈利质量

质量分 Q 使用可大规模审计的财务字段，以TTM降低单季营运资本波动：

| 输入 | 权重 | 方向 |
| --- | ---: | --- |
| GAAP经营利润率 | 25% | 高优 |
| 同口径FCF/收入 | 25% | 高优 |
| 应计比率 `(net income − CFO) / 平均总资产` | 20% | 低优 |
| SBC/收入 | 15% | 低优 |
| TTM毛利率同比变化（pp） | 15% | 高优 |

平均总资产取与TTM匹配的期初/期末，净利润与CFO合并范围一致。FCF采用明确的现金开支定义；若仅有净现金投入代理，分数与所有成员统一该代理并标识局限。重大的资产出售、供应商融资、收购范围变化等异常需单列复核状态，不能让现金处置收益自动拿质量高分。

一旦已知资产出售或现金分类变化显著影响FCF，暂停该公司的FCF质量项及依赖它的质量/综合总分，直至有统一gross现金购置或可审计调整桥；只挂提示却继续让异常值参与评分不可接受。原始披露、增长单项榜及未受影响指标仍可见。未知是否存在此影响时明确标注筛查覆盖，不宣称完全剔除了资产处置。

负经营利润/负FCF是合法观察，不转换成0，不删除亏损公司。FCF−SBC、稀释、净债务、客户集中度、库存及应收变化作为解释面板；其中客户必须分清直接采购方与最终客户，不以不同口径百分比比较护城河。non-GAAP保留发行人调整桥，不能替代统一GAAP主榜。

### 综合

`Composite = 50% × G + 50% × Q`，页面称“经营综合分”。权重、原始值、同组百分位、加权贡献和得分可以逐项展开。市值、YTD股价涨幅、估值便宜程度不混入该分；估值在Research提供独立判断。

默认硬件和软件分榜，必要时使用有足够样本的子行业基准。组内可评分成员少于8家不生成有精度幻觉的百分位榜，只提供原始指标比较；可显式切换更大的父组。全部股票视图保留两组名次；如提供跨组综合排序，必须标为“行业内相对分”，不是绝对商业质量可比。

百分位基准固定为 `asOf + quarter + universeVersion + peerGroup + methodologyVersion` 的合格成员，不随文本搜索、收入门槛、个人勾选或分页改变。筛选只改变可见行；保留基准名次，另给可选“当前结果顺序”。用户显式切换基准组才重新计算，并显示基准已变化。

缺输入不记0、不自动平均剩余权重。核心分数所需输入齐全才进入该分数榜，否则显示 `insufficient_history / missing_metric / non_comparable`，并保留已知事实和其他可用单项排名。每个榜显示可评分数/总覆盖数，避免把历史短的新公司悄悄删除。

## 9. PIT：研究季度与信息截止日分开

全局有两个独立日期概念：

- `selectedQuarter`：要研究的经营期间。
- `asOf`：用户站在哪一天，只允许使用当时已公开的信息。

例如选2026Q2，截止2026-06-30，7/8月披露的Q2数字不可见。页面可以显示Q2已披露部分，并提示最近完整可比季；不能用Q1替补Q2，也不能自动将截止日移到财报发布之后。

提供两个明确快捷键：“该季季末”设到季末；“财报季后”设到该季结束后第二个月末，界面直接展示实际截止日。后者只是观察日约定，不假定全部公司都已披露。精确日期始终可修改。

所有卡片、排名、指引、汇率、价格、客户集中度、公司分类和Research下钻使用同一个asOf。历史季度播放时，每个frame有自己的信息截止日，不用今天的数据填回去。

### 三层时间与两种历史语义

1. **经营时间**：periodStart/End与财季。
2. **公开时间**：原始公告publishedAt/SEC acceptedAt；仅有provider datekey则标为日期精度代理。
3. **系统时间**：observedAt/ingestedAt/catalogGeneration，用于重放平台实际拿到的版本。

“按当时公开信息重建”允许今天回填真正早已公开的原始文件，必须保留它原本的公开时间；“平台当时保存的快照”则还需当时系统数据版本。二者不能互相冒充。

首版承诺日粒度研究PIT：ARQ/ARY/ART来源按各自类型过滤，periodEnd和可得日都不晚于截止。只有datekey时不支持盘中判断或财报发布前成交推演；若以后加可交易回测，需要真实时间戳及下一可交易时点规则。

### 修订与成员

- 默认“截至当时可知口径”：按每个经营期间选择截止日前最新合格AR记录，与 `get_fundamental_research` 当前选择逻辑一致。AR数据只能证明其datekey精度的版本可见性；不能因此宣称供应商全部历史改写都已保存。
- “首次披露口径”作为可选比较视角，每期选择截止日前最早合格AR记录，帮助区分经营变化与后来修订。现有估值发布合同采用首次披露规则；新模块不改动该合同，并在与估值页联动时显示二者的版本差异。
- “截至当时修订”仅使用确实保留且能证明可得日的版本；同datekey后来被供应商改写而没有原始归档时，降级为日期代理回溯并显示限制，不把今天MRQ/MRT的重述当作历史信息。
- “最新修订”属于另一研究视角，页面明确显示，不标成严格历史PIT。
- 当前股票池回看称“固定篮子历史研究”；历史成员模式需要当时存在的分类/上市状态证据。旧74股配置不能支持后一种声明。
- 新公司上市/业务转型不能使用今天的分类回填此前排名。经济事实在公开后可查询，股票池资格另行判断。
- 同比/环比的本期和基期按同一个asOf及修订策略选择，不能将本期首次披露值配上今天重述后的基期。公告内提供的重述比较数保留该公告当时的公开时间与比较口径。
- 保存/分享一次分析时固定 `asOf + quarter + universeVersion + methodologyVersion + catalogGeneration + sourceRevisionIds + filters`。

## 10. Insights 如何产生

优先由确定性规则产生可核实观察，每条返回输入、计算、期间、样本、限制与证据：

- 增长扩散：收入YoY加速公司的数量/可比样本，及收入加权占比；区分“龙头拉动”与“多数公司一起加速”。
- 增量集中：前3家公司贡献多少净增量；若正负贡献互相抵消，净贡献占比可能超过100%，改为显示金额及正负贡献分组。
- 增长与质量背离：收入加速但经营利润率/TTM FCF率下降，点击查看营运资本、SBC和资本支出。
- 现金兑现：TTM经营利润、CFO、FCF变化是否同向；并购/税项等未核实原因留为待验证解释。
- 资本投入与收入增速差：展示两条增速之差(pp)及窗口，称“增速差”，不称资金缺口或回报率。

“领先几季度”是后续研究工具：只有足够长度、口径一致和稳定成员的序列才展示候选滞后相关；返回有效样本数和敏感性，考虑趋势/重叠YoY的自相关。八季图不自动宣布capex领先硬件两季，也不把相关性写成因果。

LLM只负责将结构化观察写成可读句子、连接原文证据和提出反证，不计算金额、不生成打分、不补缺失、不凭排名给买卖指令。历史摘要也必须只看到该asOf许可的材料。

## 11. 数据流与计算职责

```text
Fact OS（固定manifest、原始/修订记录、发行人身份）
    + 版本化Universe登记
    + 可验证的公司公告/分部/租赁补充事实
      ↓
PIT选择 → 季度规范化 → 单公司指标 → 同组配对聚合
      ↓
排名 + 贡献 + 观察 + 覆盖审计（确定性）
      ↓
带版本的只读快照/API
      ↓
Flutter AI Insights → 公司对比/Research → 用户研究记录
```

不复制Fact OS数据库，不在docs/output保存原始财务库。官方补充事实遵守现有append/revision-safe合同，保留来源URL、哈希、单位和会计口径。供应商更改datekey相同的历史值时，也要保留观测版本，不能靠自然键覆盖毁掉重放证据。

建议新增：

- `server/config/ai-insights-universe.json`：版本、issuer/security、主组/标签、角色、有效区间、classificationKnownAt、证据、纳入/排除原因。
- `fact_os/ai_insights.py`：季度事实批量查询、版本选择、期间/币种/符号规范化、聚合底表；通过RPC白名单暴露。
- `server/aiInsightsMetrics.js`：唯一的派生指标/分数/贡献公式实现，附公式版本；Python不维护另一份排名公式。
- `server/investmentAiInsights.js`：请求校验、快照、覆盖、轻量响应与证据。
- `lib/investment_ai_insights.dart`及其widgets：总览、排名、对比、证据和状态；不延续旧ValueFlowPanel。

基础规范化事实至少包含：issuerId、securityId、metricId、value、unit、currency、periodStart/End、fiscalPeriod、calendarProxyQuarter、periodType、scope、accountingBasis、publicAvailableAt、availabilityPrecision、observedAt、revisionId、sourceRef、generation、status。

## 12. API与快照合同

```text
GET /api/investment/ai-insights
  ?asOf=2026-09-22&quarter=2026Q2&window=8&capexBasis=net_cash_proxy

GET /api/investment/ai-insights/rankings
  ?asOf=...&quarter=...&universe=hardware&rank=quality&sort=revenue_qoq

GET /api/investment/ai-insights/companies/:ticker
  ?asOf=...&quarter=...&window=8

GET /api/investment/ai-insights/compare
  ?asOf=...&quarter=...&tickers=CRDO,ALAB

GET /api/investment/ai-insights/methodology
```

每个响应返回：asOf、selectedQuarter、periodMapping、viewMode、revisionPolicy、methodologyVersion、universeVersion、catalogGeneration、generatedAt、publishedAt、coverage、sourceRefs、status。派生快照的生成/发布时间与输入的公开/入库时间分开。overview额外返回triadSeries、capexComposition、sectorSeries、contributions、insights、rankingPreview。

metric返回原始值、单位、期间、分母、比较基期、可得日和status；score返回每项原值、百分位、权重、贡献、同组样本数和不评分原因。空值不是0。

同一次用户分析必须固定snapshotId。概览返回该ID，后续排名、公司侧栏、导出请求携带它；新generation发布后旧snapshot仍按保留策略可读，过期则明确提示重新加载整套分析，不能一个页面混合两个版本。

缓存键包含全部结果相关参数、manifest hash、schema/method/universe版本。摘要与明细分载，排名分页，顶部只加载可见窗口；不拉完整原始sourceRecord，不预加载无关13F/Guru。派生发布用manifest-last原子机制，不覆盖旧源数据。

## 13. Value Flow 的彻底退出

实施时一次性替换在线入口与渲染，不在新页中保留旧产业链卡片：

1. `lib/investment_discovery.dart` 删除valueflow标签和ValueFlowPanel挂载，新增aiinsights。
2. `lib/main.dart`替换part；旧 `lib/investment_value_flow.dart` 在引用清零后删除。
3. `investment_workflow.dart`改选择状态、URL解析、懒加载、进入/返回Research；`investment_explorer.dart`保存quarter/universe/metric/rank/basis/ticker等参数。
4. `investment_workspace_pages.dart`更新面包屑和返回文案，来源统一为AI Insights。
5. 新API上线后撤掉旧value-flow handler及其在线计算。旧API返回明确410迁移状态，不返回新shape冒充旧合同。
6. 旧UI链接转到AI Insights，保留lang/asOf；不能映射的旧stage明确重置，不随机选新子行业。
7. `investmentService.js`新记录使用 `ai_insights` + discoveryContext；已保存的 `value_flow` 历史记录保留原始出处和可读性。必要历史taxonomy只留在隔离兼容读取中，不保留旧产品能力。
8. 更新路由退役断言、部署文档、i18n与AGENTS中旧“Value Flow活跃”表述。此次用户明确替换请求已覆盖那条旧约定，无需再为删除旧界面求确认。

保留历史研究和用户记录是数据完整性，不代表保留Value Flow模块。无需恢复已退役Ontology/DBMF。

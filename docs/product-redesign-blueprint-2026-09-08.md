# ThesisForge：完整产品设计蓝图

日期：2026-09-08。依据：用户原始 guideline、本轮 11 个界面/状态的实际走查、现有 Flutter 与后端代码。

这是产品结构、逐页交互与视觉规范，不是“已经实现全部功能”的交付声明。没有改线上，也没有覆盖现有工作区。当前证据见 [产品审计](/Users/yudonglu/Documents/guru-intelligence/docs/product-experience-audit-2026-09-08.md)。

## 1. 先把产品定义对

ThesisForge 帮助有基本投资知识、但时间有限的个人投资者，完成一条能回头检验的研究链路：

**发现值得研究的公司 → 验证经营变化 → 形成自己的估值假设 → 记录决定 → 在新证据出现时复盘。**

“Evidence before narrative” 不只是口号：界面必须让事实、系统计算、用户判断有不同的位置和外观。

产品的吸引力不是更多图表，而是：**我能知道自己为什么看这家公司、当时相信什么、后来什么变了。**

不能做成聊天框、自动荐股、AI 评分、目标价排名榜。不能为了好看掩盖数据不全，不能把系统估值当成用户已经认可的情景。

### 谁做什么

| 对象 | 系统负责 | 用户负责 |
| --- | --- | --- |
| 发现 | 有出处的持仓变化、固定筛选规则、结构化产业关系 | 关注哪些经理/公司，为什么继续研究 |
| 研究 | 财报事实、管理层原话、公式、历史对比 | 对事实的解释与反例 |
| 估值 | 确定性计算、敏感性、反向求解、归属桥接 | 增长、利润率、折现率、情景和风险判断 |
| 决策 | 保存不可变快照、版本、时间、数据来源 | Watch / Pass / Invest、仓位、监控条件 |
| 复盘 | 新旧事实对照、规则触发、同假设重算 | Maintain / Change / Add / Reduce / Exit |

## 2. 信息架构：五个主入口，一家公司一个工作区

主导航顺序固定：**Home / Discover / Research / Portfolio / Strategies**。

- Home 包含 Attention、Review queue、重点观察与待继续研究。
- Discover 包含 Gurus、Fundamental changes、Value Flow；Guru 详情在 Discover 下。
- Research 是公司工作区与已保存研究入口；公司内有 Overview、Valuation、Decisions & history。Review 是从某条决定打开的有上下文工作模式，不是无对象的第六个主菜单。
- Portfolio 先明确“研究组合”或“真实账户”，再在各自数据边界内展示仓位；Fundamental、Guru Shadow、CTA 是清楚区分的组合/策略视角，不把模拟和实盘混成总净值。
- Strategies 管理规则、回测和影子组合。独立 CTA 数据未接入时明确显示未连接，不恢复已退休的 DBMF 产品。
- Account / Connections / Language / Admin 放辅助导航。Admin 仅管理员可见，不占普通用户研究区。

Research 顶部采用返回路径，例如“Discover / Bill Ackman / 2026 Q1 / MSFT”。返回时恢复经理、季度、筛选、排序、选中行、滚动位置；不是返回一个清空的首页。

### 三条必须连通的任务

| 任务 | 用户路径 | 每段留下什么 |
| --- | --- | --- |
| A：从大佬发现股票 | Discover → Guru → 季度/股票轨迹 → Research → Valuation → 决策 | 原披露 accession、持仓期、公开时间、发现路径、情景版本、决定 |
| B：从财报变化研究 | Home/基本面筛选 → Research → 新旧指标 → 假设沙盒 → 反向估值 → Watch/Pass/Invest | 明确规则、触发事实、反例、假设集合、保存的快照 |
| C：持仓复盘 | Home 提醒/Portfolio → Review → Then vs Now → Maintain/Change/Add/Reduce/Exit | 触发来源、同版本计算、主动用户动作、新复核版本 |

Watch 和 Pass 是有效终点。不是所有用户都必须走到 Invest；不能把提高交易次数当作产品成功。

## 3. 每个界面怎么设计

### 01 · 公开案例与登录交接

**用户问题：这个产品到底能帮我做什么？**

保留目前公开 ISRG 页较清楚的结构：一个问题、一条真实曲线、明确日期、三个可挑战假设、变化解释、反例。不要在首屏展示整个终端的所有模块。

页面主操作为 `Explore this company`；进入同一家公司的研究页，保留案例日期和来源。公开内容仅用许可范围内已审核的快照；不为免登录暴露付费原始数据或用户记录。

登录应发生在需要持久化或访问私有数据的时候。若许可/鉴权不允许匿名编辑，直接说明边界，提供只读案例，不展示无法完成的保存按钮。登录后回到原 ticker、tab、日期和待保存草稿，不回首页。

视觉：可读叙事宽度 720–800px，曲线最多延展到 1120px。登录是居中、短表单；底部背景完整铺满，手机键盘打开后按钮可达。不用大幅通用金融插画。

状态：匿名、登录中、失败可重试、过期链接、登录成功返回原任务。验收必须实际走一次登录往返，不只测页面可打开。

### 02 · Home / Attention

**用户问题：今天有什么值得我处理？**

老用户首屏：标题 `Your research, since your last review` + 真实数据截止日；主要内容是待复核队列，不是宣传口号。

桌面内容采用约 2:1 两列：

- 主区：待复核行列表，每行有公司 Logo/名称、具体变化、Then → Now、报告期、公开日期、命中的用户规则、`Review changes`。
- 辅区：最近未完成的两三项研究，显示“情景未保存 / 已观察 / 待复核”；下面小型组合摘要，只出现真实可用指标。
- 下方：三条可追溯发现入口，不列 87 个股票代码。

如果有多个提醒，排序基于公开的规则：用户设定严重度 → 新公开时间 → ticker 稳定 tie-break。不是黑箱投资机会分数。

无提醒时使用紧凑 `No new rule breaches at this cutoff`，保留继续研究；不占一张巨大的空卡。首次用户没有组合时，首屏为 `Start with a Guru or a company`，让用户开始第一条研究，不先要求连接券商、填风险问卷或配置 CTA。

手机顺序：截止日 → 最高优先级待办 → 继续研究 → 发现 → 组合摘要；不把五层导航堆在最上面。

完成标准：用户能在首次可见区域说出需要复核的公司、原因和下一步；若队列为空，也能找到继续研究的明确入口。

### 03 · Discover / Gurus

**用户问题：我关注的投资者最近披露了什么，哪家公司值得打开？**

默认显示 Gurus。Fundamental changes 和 Value Flow 是同层切换，不同时挤在首屏。

页面上方：标题、公司/经理搜索、数据截止日。其下是 `Following / All managers`、报告季度和 `New / Increased / Reduced / Exited`。四类动作仅用于已完成可比性核验的披露；不可比公司行动单独标记，不强行归类。

主内容是连续披露列表，不是关注开关列表：

| 每条披露 | 展示要求 |
| --- | --- |
| 身份 | 经理头像与基金名；公司 Logo、ticker、公司简称 |
| 事实 | 动作、上季股数→本季股数、股数变化率、当前披露权重 |
| 时间 | 持仓截至日、公开日期；点击可到原 filing |
| 下一步 | 点公司 → Research；点经理 → Guru 详情；Follow 独立操作 |

“集中持仓”和“集中加仓”做 Market Lens 子视图。明确经理集合和分母，不能把持仓多等同于新增买入多。卡片中的经理头像可点，选股票后解释哪些人、哪一季、变化多少。文艺复兴等广泛系统化持仓遵循现有排除集中度榜的规则。

首次没有 Follow：给出可浏览的经理目录，按披露类型分组，不默认替用户关注三人；关注后才把相关披露加入个人 feed。

桌面：一张有稳定列宽的研究表，右侧详情只在选中时打开。手机：同一行变为“公司 + 经理 / 变化 / 日期”三行，不压缩成小号密集表格。

### 04 · Guru detail / 季度持仓工作区

**用户问题：这位经理持有什么？哪个季度变化？这只是披露还是可复制的策略表现？**

页头压到一行身份 + 一行关键元数据：头像、经理/基金全名、Follow、持仓截至日、公开日、Reported 13F value、普通股多头/期权范围。不要把基金名、日期截成省略号。

内容导航保留四个清晰任务：`Holdings & changes / Position history / Copy simulation / Contributions`。复用原模块，不重写其投资数学。

持仓与轨迹采用主从视图：左 55% 为当前季度股票表，右 45% 为选中股票的历季轨迹。轨迹可切 `Shares / Weight / Reported value`，默认突出股数，权重变化另作解释。行选中只改变轨迹，明确的 `Research company` 才跳转，避免两个点击动作冲突。

季度选择用年份分组的选择器 + 紧凑前后季度按钮，不把 40 个季度铺成一堵 chips。图表有实际覆盖起止与可拖动区间；单季缺席于 Top10 不显示“退出”。

Copy simulation 复用 1Y/3Y/5Y/10Y/All 与自由区间条；首屏能看到曲线和条。5Y 默认；10Y 按需载入，All 仍是可失败的 forensic 查询。当前严格/代理口径和覆盖范围要可见，不藏到一大段方法下；详细解释折叠在图后。

原三栏中的全市场 Lens 在专注经理研究时收为可展开侧栏，避免主图和经理头被挤窄。专注模式不删除原终端能力。

### 05 · Discover / Fundamental changes

**用户问题：哪些公司的经营数据出现了值得验证的变化？**

把 chips 改成可排序表：公司、报告期、公开日、收入同比、同比增速变化（pp）、经营利润率变化（pp）、FCF 转化、触发条件。最多 6–7 个默认列，其他自定义。

默认筛选必须写成可理解的条件；当前只有“最新季度收入同比≥15%”，应如实命名 `Revenue growth screen`，不得先叫“基本面拐点”。只有接入经过定义的加速/利润率改善规则后才能提供相应 preset。

筛选工具让用户改规则、看到匹配数量、清空、保存版本。排序规则透明；历史百分位有样本窗口与样本数。没有经过审计的同业集合就不显示 peer percentile。

选择公司时在右侧预览真实变化与来源，主操作 `Open research`；打开后来源写这一筛选规则及其版本，而不是碰巧持有该股的大佬。

### 06 · Discover / Value Flow

**用户问题：这家公司在产业链中做什么，与哪些变化有关？**

复用现有 Ontology 图，进入选定产业链或保留上次图谱，不默认铺全宇宙。图是主区域，选中节点打开 320px 公司/证据侧栏。

右栏只显示结构化角色、关系类型、证据、覆盖日期、已披露经营变化。明示“公司披露关系 / 结构推断”区别；不存在经证实因果关系时不写成“因此业绩将增长”。

`Research company` 进入相同 Research，并携带节点与关系来源。图谱本身不变成买入信号或另一套公司详情页。缺节点可按公司搜索并明确“不在当前图谱”，不要随机定位到替代公司。

### 07 · Research / Overview

**首屏必须回答四件事：为什么看它、变了什么、变化是否异常、估值处于什么状态。**

公司头不再用 43px 名称占大片高度：Logo 40px、名称 28px、ticker/行业/财报期/公开日紧凑排布。顶部常驻来源 breadcrumb、数据截止日和保存状态。

首屏布局：

1. `Why this company?` 一行真实入口，另列“同时发现的证据”，两者不可互相替换。
2. `What changed?` 三到四个有前值→现值和时间的指标，不只是当前大数字。
3. 主区约 2/3：财务趋势或价格/估值图，用户可切换，但同一时刻只突出一张图。
4. 右侧约 1/3：模型状态、已保存个人情景（若存在）、`Open valuation`。没有个人情景时写“尚未建立”，不把平台 Base 当作用户自己的判断。

第二屏逐层展开：经营数据、管理层指引、财报/Q&A、相关 Guru、Value Flow、原始证据。管理层原话和系统推导独立标注，公式预测不是管理层指引。

图上选择报告点后：当前选中的季度、当时公开的基础数据和估值变化解释联动。缩放不更改底层时间序列；缺失期显示中断/未建模，不平滑补造。

### 08 · Valuation / 假设工作台

**用户问题：我相信怎样的增长和现金流，这样的价格值不值得继续考虑？**

这里优先展示“计算与判断”，不再次展示一张占满高度的同款历史大图。

桌面采用中间 8 列 / 右侧 4 列：

- 顶部：`Published model` 与 `My scenarios` 明确切换。平台混合估值和个人 DCF 必须保留方法名，不能用同一个无上下文的 Fair value 标签。
- 中间：实际期与预测期分界的五年表；收入、增速、现金流利润率、FCFE/FCFF、折现因子、现值。默认 3 个关键驱动，其余展开行，不再展开另一整页重复表单。
- 右侧：固定、窄而清楚的 Bear/Base/Bull 结果对照、当前沙盒版本状态、价格与模型差值、保存情景主按钮。三情景不强制用户认可系统模板。
- 下方：敏感性和价值桥接。选择一个敏感性格子只预览，按 `Apply to draft` 才应用到草稿。

现金流类型决定组件：Parent FCFE 显示 Ke、股数、归属调整且不二扣债/NCI；FCFF 显示 WACC 和 EV→Net debt/NCI/claims→Equity→Share 桥；银行/保险/SOTP 显示适用方法，未支持编辑时保持诚实只读，而不是套普通企业 DCF。

变更流程：编辑 → 即时沙盒结果/有效性 → 与保存版差异 → 保存新版本。更新财报仅提出新实际基准，不覆盖用户预测。切公司、语言、日期或返回时，脏草稿提供保留/放弃选项；未完成请求不能让旧计算贴到新 ticker。

`$313.54 vs $178.02` 这样的差异不能靠两个标签解决：提供可展开的“平台综合估值包含哪些组件；个人仅算哪种现金流；基准日期/参数是否一致”。未做可比桥接时明确写“不同方法，不是模型涨跌”。

### 09 · What must I believe? / 反向估值

**用户问题：当前价格要求经营达到什么程度？**

放在 Valuation 内可切换的独立视图，不是一个孤立大百分数。

左侧输入：价格及观察日、目标回报率、求解变量（五年统一收入增长，或终期利润率）、预测期。固定变量折叠但结果旁有摘要。目标回报率和正向模型 Ke 的关系必须说明：明确“跟随当前 Ke”或“独立目标回报率”，不能用户改 Ke 却不知道为什么反推不变。

右侧：结果句子，例如“在这些固定条件下，未来五年需要每年 X% 收入增长”，再对比实际历史窗口与用户情景；所有数字从真实求解结果来，不用静态营销示例。

结果包含求解边界、回代误差和限制；无解时显示“在设定边界内无解”，不显示 0%。不为所需增长自动判定“合理/不合理”。`Use as comparison` 不覆盖用户预测。

### 10 · Decision / 快照确认

**用户问题：我准备做什么，以及将来什么证据会让我重新检查？**

三段连续、可返回的流程，不是一屏所有输入：

1. **Choose**：Watch / Pass / Invest，同等视觉权重，无默认选择。
2. **Record**：显示已保存/待保存的情景版本、发现证据、个人理由与反例。Invest 才要求研究仓位；Watch 才显示是否重点监控；Pass 不强迫填目标权重和仓位。
3. **Confirm snapshot**：冻结日期、价格、实际基准、情景集版本、原始来源、规则、笔记与仓位；主按钮 `Save decision`。提交前有“研究记录，不是券商订单”。

有未保存情景时就地完成“保存情景并继续”，不要先让用户填整页、最后才禁用按钮。模板规则以未启用示例展示，只有用户主动确认才入快照。

规则编辑是一句可读句子：“当 [指标] [低于] [阈值及单位]，连续 [N] 个新报告期，提醒我复核。”详情可设置观测窗口、适用范围和严重度。规则创建必须验证指标覆盖。

成功状态给出新快照版本和两个真实去向：`View decision`、`Open portfolio/watchlist`。重复点击不重复记录；不把 Pass 做成二等灰色按钮。

### 11 · Decision history / 决策档案

**用户问题：我当时到底依据什么作了决定？**

公司内历史按真实版本排列：日期、动作、数据截止日、情景版本、价格、研究仓位、用户笔记。默认显示人能读懂的快照，不展示 JSON。

选一个版本即打开只读档案；“当时市场数据”与“今天查看时的价格”不可混放。明确 recordedAt 与历史研究截止日，回溯研究不能伪装当时真实发出的预测。

能比较两条用户确认版本；标出实际数据改变、假设改变、仓位改变、监控条件改变。编辑旧笔记也必须创建新修订，不覆盖原记录。原始机器数据保留为高级审计入口。

### 12 · Monitor / 规则与事件

**用户问题：哪条新证据触及了我自己设定的条件？**

Home 的 Review queue 是入口；完整事件列表可按持仓/重点观察、规则、严重度、公开日期过滤。

每行：公司、规则全文、前值→现值、来源时间、连续期数、状态、`Review changes`。状态至少区分未触发、需要复核、已复核、数据不足、待更新。缺失观测不能算满足，也不能默认为通过。

同一规则/同一新证据不能重复刷屏；一家公司多个触发可合为一个 review task，但保留所有原事件。Maintain 后事件变为已复核；下一报告期仍可再触发。后台任务未实现时明确写“当前按打开页面/切换日期计算”，不能宣称持续实时监控。

Guru 减股只触发事实复核，列出持仓日、披露日和公司行动状态，不写成经理“转空”。

### 13 · Review / Then vs Now

**用户问题：是公司变了，还是我的假设变了？现在我如何处理？**

顶部是复核原因、原决定日期和本次新证据日期，不重复一张 Research 大头图。

中部采用清楚的对照表：

| 指标/计算 | THEN：所选确认版本 | NOW：新事实、同一套假设 | CHANGE：本次草稿 |
| --- | --- | --- | --- |
| 财务实际 | 当时可用期与数值 | 新公开期、数值、变化 pp/% | 不可被用户编辑成事实 |
| 预测 | 所选版本路径 | 明示保持该路径/规则不变 | 用户主动修改的行高亮 |
| 估值 | 当时同方法结果 | 新实际基准重新计算 | 修改后结果与新增差异 |
| 来源 | 当时快照 | 新财报/新披露证据 | 用户补充的判断 |

默认对照“最后确认的版本”；另有“最初决定”切换。标题必须随选择变成 v1/v2 等，不能左栏引用 v1、右栏用 v2 却统称旧假设。最终价值变化可以先采用固定顺序桥接，披露替换顺序及交互项；不把所有变量的独立敏感性简单相加。

底部常驻操作区：Maintain / Change / Add / Reduce / Exit 同等可选择，默认无选择。Maintain 不改预测，但需要记录已检查的新证据；Change 在当前复核上下文打开编辑器，保存情景后自动返回此 review，而不是让用户自行找回来。

手机把表拆成逐指标 Then→Now 对照，原假设与新草稿可切换，不把三列缩成小字。不自动从低估推出加仓。

### 14 · Portfolio / 组合工作台

**用户问题：我持有什么、承担什么风险、哪一项需要研究？**

页头明确账本：`Research portfolio` 或真实已连接账户；不同货币需要来源清楚的已验证 FX 后才能聚合。研究组合与真实账户不能共享一个看似完整的 Equity 总值。

研究视角首屏只留四个真实可用摘要：仓位数、研究市值、最大权重、待复核数；未算出的收益率、风险和成本不要占大卡伪装 0。

主要内容为仓位表：公司、实际研究权重、成本覆盖状态/现价、已确认情景价值、监控状态、最后复核日、`Review`。按需展开行业/暴露、情景回报、集中度；使用旧账户组合的可靠组件和已审计数据，不另造简化账户。

Watch/Pass 放 `Watchlist / Decision journal` 标签页，不重复占据 Portfolio 首屏。来源及范围是每行可展开字段。

Guru Shadow 对照页明确规则版本，分别列共同持有、用户额外加入、用户排除、权重差异；只有窗口/币种/价格/执行/成本口径对齐时才能显示业绩比较。当前披露预览不能冒充模拟策略仓位。

CTA 在策略视角显示单独连接状态；真实数据未接入时用一条简洁说明与需求入口，不用无数 disabled 图表。接入后才展示权益/CTA/合成组合和同窗口风险，永远不暗示无条件对冲。

### 15 · Strategies / 规则与模拟

**用户问题：这条简单、透明的规则过去如何运行，与我的主观组合有什么差异？**

入口显示已保存策略版本和可用模板。模板不是已替用户配置好的策略。Guru Top 3 创建流程须展示经理集合、TopN、排名字段、去重、权重、披露/执行/再平衡、成本与数据范围，再由用户保存。

详情默认曲线、基准和真实窗口，保留旧引擎的区间条；收益、超额、MDD、成本、覆盖状态紧凑排列。规则版本与计算版本常驻，Detailed methodology 在图下。

`Rules / Holdings / Performance / Contributions` 是同一策略的视图。改 TopN、加入估值条件或更换经理必须成为新策略版本；新增 DCF 过滤不能偷偷改变既有“抄作业”定义。

失败时保留最后可用结果并明确其窗口/版本/陈旧状态；新请求不能冒认成功。所有 missing identity / execution coverage / proxy 等错误用可读原因与对应范围呈现，不只是 backend exception。

### 16 · Evidence drawer / 来源与方法

所有页面复用同一个 400–440px 抽屉，手机全屏。

按“数据 → 计算 → 解释”三层组织：指标名称/值/单位、财报期/公开日期、原始出处、使用的原始字段、转换/公式、中间结果、最终数值、排除原因。引用官方管理层指引时原文和 model consumed 状态并列。

用户不需要读 JSON 就能找到数值来源；JSON/export 在高级区。来源抽屉关闭后回到原控件，不能打开新的迷宫。数据库内部字段名和红色 stack trace 不进入主产品。

### 17 · Account / Connections / Admin

账户页：语言、时区、已连接账户、数据同步时间、退出。连接出错要区分未授权、授权过期、同步失败和没有仓位，恢复不会覆盖研究快照。

Admin 单独入口：最近登录排序，`Has portfolio / No portfolio` 两组，明确上次登录时间/时区、注册时间、组合状态；没有记录显示未记录而不是注册时间代替登录。搜索、分页、身份与权限边界独立验收。

本轮未访问真实用户目录或登录写操作，因此这是目标设计，不是已通过审计的 Admin 状态。沿用现有 AdminLoginActivityPanel / AdminUserDirectoryPanel，不在普通研究 shell 新造一套管理系统。

## 5. 状态设计和信任边界

| 状态 | 展示 | 可做的事 |
| --- | --- | --- |
| 首次使用 | 一句话价值 + Guru/公司入口 | 不要求先连接账户 |
| 未匹配 | 当前筛选条件和 0 个结果 | 清空/放宽自己设定的条件 |
| Loading | 保留布局，说明正在取哪类数据 | 不显示旧股票结果为新股票 |
| Stale | 最后可用时间、请求/实际窗口、原因 | 查看已知结果/重试；不冒称最新 |
| 未覆盖估值 | 确认 ticker 身份、缺失项目、研究仍可读 | 返回持仓/看财务；不显示空白页或替代股票 |
| 不适用模型 | 经济口径/适用方法说明 | 使用可用只读研究；不强套 DCF |
| 网络错误 | 具体失败步骤，不与未建模混淆 | 重试且保留用户输入 |
| 草稿未保存 | Draft/Unsaved 状态与改动摘要 | 保存新版本/保留草稿/丢弃 |
| 历史回放 | 常驻日期，分开记录实际保存时间 | 只看当时公开数据，明确不是当年实时记录 |
| Saved | 明确版本与来源 | 打开快照，继续原任务 |
| 无权限 | 什么需要登录/管理员资格 | 登录后恢复上下文，不能泄露他人数据 |
| 数据不齐 | 缺失范围、对结果的影响 | 不出不可靠聚合，不把 null 变成 0 |

信任文案是简短标签 + 可展开解释，不是在每页开头重复一大段免责说明。关键限制（模拟不是实盘、披露有滞后、归属口径）必须贴在相关图表或操作旁。

## 6. 实现规划：复用引擎，抽出页面，不继续扩充巨型文件

以下为计划，不是已创建的文件结构。

| 范围 | 复用现有 | 需要建设 |
| --- | --- | --- |
| Shell | LanguageScope、Palette、Logo、身份/鉴权 | WorkflowRouter，统一截止日/路径/返回状态，草稿离开守卫 |
| Discover/Guru | GuruUniversePanel、GuruAvatar、GuruWorkspace、Market Lens、position history、simulation、contributions | 统一 Discover/Guru 页面适配；manager/quarter/filing 来源上下文，不硬编码姓名 |
| Research/Value | StockLogo、ValuationTrendChart、PIT model runs、guidance、原经济模型 | ResearchHeader/ChangeSummary/EvidenceDrawer；预测表/情景比较/方法切换 |
| 决策/复盘 | investmentMath、Store、Service、不可变快照 | ScenarioSetVersion、Decision confirmation、明确比较基准、ReviewContext |
| Portfolio | 现有 PortfolioDashboard、真实连接/成本/持仓组件 | 研究/实盘范围开关，研究快照关联，shadow 同口径比较 |
| Strategies | 原 Guru 回测与去重/时间/价格门禁 | 可见规则编辑与版本，不在按钮内写死3人 |
| Value Flow | web/ontology | 深链和只读关系来源，统一股票去向 |
| Admin | admin_login_activity、AdminUserDirectoryPanel | 在新 shell 保留授权入口，验证排序与分组 |

代码组织建议：lib/workflow/shell、discover、research、valuation、decisions、review、portfolio、shared。保留 main.dart 的组合入口，逐个抽出现有组件，避免把整套第二产品继续加进 investment_graphite.dart / investment_workflow.dart。

路由至少保存公司身份、页面子模式、截止日、经理/季度/filing、入口类型和返回位置。持久快照引用不可变证据 ID；个人笔记、持仓详情和 token 不进入 URL。SourceContext 与“相关 Guru 持有证据”是两个对象。

计算、价格/数据版本、用户版本分层。切截止日同时校验财报、指引、FX、价格和 Guru 可见性。不能让新工作区的历史截止日只约束一半组件。

### 实施顺序与退出条件

1. **先修产品信任问题**：假来源、日期丢失、错误零值路径、默认决策/仓位、固定经理保存。每项有复现和回归，未通过不继续宣传完整流程。
2. **第一段完整体验**：Discover → Guru → 季度/股票轨迹 → Research；验收返回上下文、真实 Logo/头像与真实数据，而非只截一个好看的研究页。
3. **第二段完整体验**：Research → Valuation/Reverse → 主动决定 → 快照；同时交付未覆盖股票和不适用模型路径。
4. **第三段完整体验**：Home/Portfolio → 规则事件 → Review → Maintain/Change → 新快照；原快照哈希不变。
5. **整合而不是占位**：Strategies 原回测、Value Flow、已有账户 Portfolio、Admin 接回统一壳；CTA 无引擎就保持明确的未连接边界。
6. **全流程视觉/交互验收后发布**：新旧能力清单逐项对照，未达到目标的页面不能因为 build 通过被写成完成。

## 7. 设计验收：不再用测试数量替代体验

### 任务验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 新用户从公开案例进入 | 不丢公司/案例日期；登录后不回首页；公开许可范围正确 |
| 经理→季度→股票 | 可比较股数/权重；保留 filing 日期，返回恢复原季度；不推断买入动机 |
| 基本面→MSFT | 来源为实际筛选规则，不是 Ackman；其他 Guru 单独列证据 |
| ISRG 与 MSFT 两家公司 | 两家公司分别走完整 UI 保存与跨期复盘，不能仅一家公司点击、另一家只测函数 |
| 平台值 vs 我的值 | 用户能分清混合估值/独立现金流估值，找到对应方法和输入 |
| 改 Ke / 反推 | 正向结果更新；反向用哪种目标回报口径明确；回代在声明误差内 |
| Watch / Pass / Invest | 无预选；条件输入不同；不发单；保存幂等、账号隔离 |
| Maintain / Change | 基准版本明确，Maintain 不改假设；Change 新版本；历史记录不变 |
| 未覆盖/缺价格/模型不适用 | 无假数据，无空白死路，财务研究和返回动作仍可用 |
| 历史数据切换 | 所有来源与公开日期≤cutoff；草稿不丢；旧请求不污染新日期 |
| 所有已有 Guru 曲线入口 | 原 required window matrix 与区间条功能不回退；代理范围如实显示 |
| 手机/中文 | 390×844 和桌面 1280×720、1440×1000 逐页逐弹层验证；无溢出、截断主数据或不可达主操作 |
| Admin / 账户 | 真实鉴权；上次登录排序和组合分组正确；研究账本不冒充真实账户 |

### 衡量是否更容易用

以下是计划验收目标，不是当前已测结果：

- 首轮找 5 名目标用户，不指导操作。至少 4 人能说出“发现→自己的估值→留档→新证据复盘”，而不只是“看股价的网站”。
- 至少 4 人在 10 秒内识别 Home 首要任务/空状态下一步；数据多寡保持同样测试样本。
- 至少 4 人不求助完成 Guru→股票→季度变化→Research；初次目标用时 ≤90 秒。
- 至少 4 人能正确区分财报事实、平台模型、自己的假设，并分清原始决策与当前复核版本。
- 已了解金融概念的用户能在 3 分钟内完成修改一项假设、看变化并保存 Watch/Pass/Invest 任一决定；不要求为了验收增加仓位。
- 指标记录任务成功率、错误跳转、回退/重输次数、完成时间，不以点击数或交易次数作为唯一成功指标。

无障碍：按钮/链接/单选组正确语义，标签读数，键盘全链路，焦点恢复；对比度逐态测量，图表有等价数据表，颜色之外有文字区别。视觉检查不能代替 VoiceOver/键盘验证。

性能：筛选/经理/曲线分层按需加载，较长窗口沿用旧缓存门禁；同快照/运行环境复测 API p95 和首屏任务延迟。沿用 AGENTS 的性能回归合同，不能用本地感受宣称线上快了多少。
